# Feature-Completeness Audit — Module by Module

**Method:** discovery-driven inspection of every API route (~238), dashboard page
(~90), and schema table (~148) on branch `docs/enterprise-blueprint` (June 2026).
Nothing was assumed complete; each module was checked for CRUD coverage, screen
coverage, reachable lifecycle states, validations, relationships surfaced in UI,
and dead schema. Benchmarks: monday.com, Zoho (Invoice/Inventory/Books/People),
Odoo, ERPNext, SAP Business One, ClickUp.

**Companion docs:** the [blueprint](../README.md) defines the architecture; this
audit defines **feature depth** — what each module must gain to be a fully baked
enterprise product.

## 2. Cross-cutting platform gaps (fix once, every module inherits)

These recur in **every** suite audit; fixing them per-module would be waste.
They define the platform work-items P1–P12 referenced throughout:

| # | Gap (today) | Enterprise baseline (target) |
|---|---|---|
| **P1** | No list endpoint has pagination, search, sort params, or rich filters — all return everything ordered by `createdAt desc` | Standard list contract: cursor pagination, `q` search, typed filters, multi-sort; one shared query helper + the `DataTable` kit |
| **P2** | Masters and several documents **hard-delete** with no referential guards (vendor with open POs, customer with invoices, product on BOMs, board with items) | Soft-delete/archive everywhere (`archivedAt`), restore, delete guards returning "blocked by N linked records", trash view for Work OS |
| **P3** | **No duplicate/clone** anywhere (boards, items, templates, estimates, POs, process templates) | Clone on every document & template (monday/Zoho table stakes) |
| **P4** | No saved views/filters (client-state only) | `saved_views` table (user/workspace scope, per collection page): filters, sort, visible columns, view type |
| **P5** | **No PDF** for estimates/SOs/POs/invoices and no real email send ("send" = status flip; only e-sign actually emails) | Document PDF service on `pdfTemplates` (exists, only inspections use it) + branded email send with attachment + log |
| **P6** | **Unreachable statuses** across modules: invoice `void`/`overdue`, SO `pending_approval`, estimate `expired`, JE `posted`, BOM `active/archived` | Every enum value reachable via an explicit transition endpoint or a sweep; CI test enumerating enum coverage |
| **P7** | Sub-entities are create-only or create/delete-only (BOM lines, vendor contacts/addresses/banks, vendor items, locations, recurring templates, portal contacts) | Full edit on every sub-entity; UI inline-edit via kit |
| **P8** | **Dead schema**: fields never read/written (`overReceiptTolerancePct`, `matchStatus`, `fxRate`, `policyViolation`, mileage fields, `onHold`, `isPreferred`, `isVerified`, `currentRevision`, `settledMinor`, `sourceType` on JEs) and zero-route tables (`planningScenarios`, `pmSchedules`, board templates) | Each dead field either implemented (most are real features half-declared) or removed; tracked in §3 register |
| **P9** | No attachments or comments on business documents (only board items have comments; only inspections/e-sign/expense-receipt touch files) | Generic `attachments` + reuse `comments` polymorphically (`refType/refId`) → RecordPanel tabs on every document |
| **P10** | Record pages don't show related records or activity (customer page has no invoices tab; asset has no history; invoice doesn't link its SO/shipment) despite FKs + feed existing | `RecordPanel` standard: Details / Lines / Linked / Documents / Approvals / Activity on every record ([blueprint 07](../07-ui-ux-design-system.md)) |
| **P11** | Import/export: ~10 master entities, headers only, CSV only | Full registry: all masters + documents with lines, validation preview, column mapping, XLSX |
| **P12** | No global search, no bulk actions, no notification-preferences UI | ⌘K search across masters+documents; bulk select/update on lists; prefs page on existing table |

## 5. How this feeds the roadmap

- Cross-cutting P1–P12 land as **Phase 1.5 "product completeness"** workstream
  alongside the connective-tissue work in [blueprint 08](../08-roadmap.md) —
  most are platform mechanisms (list contract, soft-delete, attachments, PDF
  service, saved views) that the UI kit (Phase 3) then surfaces uniformly.
- Per-module "missing essentials" are scheduled with their suite's UI
  convergence so each suite exits Phase 3 *feature-complete*, not just restyled.
- The dead-schema register is a standing backlog: nothing new ships with dead
  columns (CI check), and each existing item gets an implement-or-remove call.
