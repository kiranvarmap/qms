# Audit 02 — Sales & Finance (Customers → Estimates → SO/Shipments → Invoices → Books, Expenses, Portal)

Cross-cutting gaps P1–P12 ([README §2](README.md)) apply throughout.
✅ verified working · ⚠️ half-baked · ❌ missing.

---

## 1. Customers & contacts

### Exists today
- Customer CRUD + portal-contact management page; customers referenced cleanly
  by estimates/SOs/invoices; CSV import/export.

### Half-baked / missing (verified)
- ⚠️ `business_contacts` (customer contact persons) have **no API routes** —
  set at create, unmanageable after.
- ⚠️ Portal contacts: create+list only — no edit, no delete, no password
  reset/invite flow.
- ❌ **No customer 360°**: detail page shows name/email/portal access but no
  AR balance, no estimates/SOs/invoices/payments tabs, no credit standing.
- ❌ No credit limit / payment terms enforcement; no customer statement; hard
  delete with open documents.

### Enterprise target model
*Benchmark: Zoho Books customer.*
- Customer RecordPanel: Overview (AR balance, overdue, lifetime value, terms) /
  Estimates / Orders / Invoices & payments / Credit notes / Contacts (full CRUD)
  / Portal access / Documents / Activity + comments.
- Credit limit + terms with soft/hard enforcement at SO/invoice creation;
  statement PDF + email; merge-duplicates utility; archive with guards.

## 2. Estimates / quotes

### Exists today
- Full draft lifecycle: create/edit(draft)/send/accept/reject/revise (immutable
  `estimate_versions` snapshots ✅ — best-in-app pattern)/convert to SO or
  invoice with `converted_from` linkage and events. Portal accept/reject ✅.

### Half-baked / missing (verified)
- ⚠️ `expired` status never set (no sweep despite `validUntil`).
- ❌ No PDF, no real email (send = flag flip + portal visibility).
- ❌ No duplicate; no void/withdraw after send; DELETE handler absent.
- ❌ Price lists never applied to line pricing; no discount approval rule.

### Enterprise target model
*Benchmark: Zoho/Odoo quotations.*
- Add: PDF on `pdfTemplates`, branded email with attachment + view tracking
  (viewed exists), expiry sweep → `estimate.expired` + reminder, duplicate,
  withdraw (void) transition, optional discount-threshold approval policy,
  price-list application with margin display, win/loss reason on reject →
  pipeline reporting (win rate, cycle time, pipeline value).

## 3. Sales orders, shipments, returns, recurring

### Exists today
- SO lifecycle with reservation discipline ✅: approve→`reservation` movement;
  cancel→release; shipment pick/pack/ship/deliver with **single on-hand
  deduction at ship** ✅; per-line qtyReserved/Shipped/Invoiced guards ✅;
  invoice-from-shipped ✅. Returns draft→posted. Recurring orders API exists.

### Half-baked / missing (verified)
- ⚠️ `pending_approval` unreachable — draft goes straight to approved; the
  approval engine is **not** wired for SOs.
- ⚠️ Shipments: **no detail endpoint/page, no edit (carrier/tracking), no
  cancel** — corrections impossible; no standalone shipments queue screen.
- ⚠️ Returns: posted is terminal; `restock` flag doesn't post the reverse stock
  movement; page buried under sales-orders.
- ⚠️ Recurring orders: no UI, no cron generation (manual generate endpoint).
- ⚠️ Price lists: full CRUD exists but **never consulted** when adding lines.
- ❌ No backorder handling (partial availability → remainder tracking); no
  delivery-date promising (ATP); no SO PDF/email; estimate/invoice links not
  shown on SO detail.

### Enterprise target model
*Benchmark: Odoo sales + Zoho Inventory orders.*
- Wire SO into approval engine (threshold/margin policies); shipments become
  first-class (detail page, edit, cancel-with-reversal, pick-list & delivery-note
  PDFs, shipments queue screen, partial + backorder generation).
- Returns: RMA flow with restock movement, credit-note generation option.
- Price lists applied at line entry (customer default → override with
  permission); recurring orders generated by sweep with failure alerts.
- Fulfillment reporting: open orders by status, ready-to-ship, backorders,
  OTIF, fill rate.

## 4. Invoicing / AR (+ credit notes, recurring, dunning, payments)

### Exists today
- Invoice lifecycle draft→sent→partially_paid→paid with manual payments ✅,
  write-off ✅, dunning-level endpoint ✅, AP-bill list page (kind='ap'),
  credit-note create, recurring-invoice create+manual generate. Invoice-from-SO
  with double-billing guard ✅.

### Half-baked / missing (verified)
- ⚠️ **`void` unreachable** (must hard-delete — audit-hostile) and **`overdue`
  never set** (no sweep wired despite service code existing).
- ⚠️ Payments: overpayment not blocked (`amountPaid > total` possible);
  payments immutable with **no reversal/refund** path.
- ⚠️ Credit notes: `applied` status has no apply-to-invoice transition; no UI
  beyond list; not netted into customer balance.
- ⚠️ Recurring invoices: no cron, no edit, no UI.
- ⚠️ Dunning log written but never displayed; no automated reminder schedule.
- ⚠️ AP bills: created via generic invoice + kind hack; no dedicated create
  flow, no detail route, no payment scheduling, not linked from PO receipt.
- ❌ **No invoice PDF**, no email-with-attachment, no payment receipt.
- ❌ Multi-currency: `fxRate` stored, never applied.

### Enterprise target model
*Benchmark: Zoho Invoice/Books — the explicit bar here.*
- **Lifecycle completion:** void transition (with reason, blocked when paid),
  overdue sweep + aging buckets, payment validation (≤ balance) + refund/
  reversal entries, credit-note application allocating against invoices.
- **Documents:** PDF templates per workspace (logo/branding), email send with
  attachment + delivery log, payment-receipt PDF, customer statement.
- **AR operations:** dunning schedule (N levels, per-customer opt-out, sweep-
  driven), AR aging report, collections inbox; recurring invoices cron-generated.
- **AP:** dedicated bill entry (from PO receipt or standalone), bill approval
  policy, payments-due calendar, vendor statement reconciliation; 3-way match
  surfaced here.
- **Screens:** invoice RecordPanel with payments timeline, linked SO/shipment/
  credit notes, dunning history, activity; AR dashboard (DSO, aging, top
  debtors).

## 5. Books / accounting

### Exists today
- Schema is genuinely double-entry (accounts typed asset/liability/equity/
  income/expense; JE lines validated debit=credit on create). Manual JE create
  + list; trial balance report + page; COA list page; CSV export of accounts.

### Half-baked / missing (verified)
- ⚠️ **Nothing posts automatically** — `sourceType/sourceId` on JEs never set;
  invoices/payments/expenses/COGS leave no ledger trace.
- ⚠️ JE `posted` status unreachable; no JE detail page (can't see lines!), no
  edit, no reverse/void.
- ❌ No COA management UI (import-only); no P&L, balance sheet, cash flow, GL
  drill-down; no date-range on trial balance; no accounting periods/closing;
  no tax reports.

### Enterprise target model
*Benchmark: Zoho Books / Odoo accounting (lite — not a full ERP GL).*
- Posting rules config (event → Dr/Cr accounts) + `runGlPosting` consumer
  ([blueprint 04 §7](../04-module-relationship-map.md)): invoice.sent → AR/revenue/tax;
  payment.recorded → cash/AR; shipment.shipped → COGS/inventory;
  expense.reimbursed → expense/cash; bill → AP.
- JE lifecycle: draft→posted (immutable)→reversed-by; detail page with lines +
  source-document link; period table with soft close blocking back-dated posts.
- Reports: GL with drill-down, P&L, balance sheet, trial balance with date
  range — all reading `journalLines`.
- Keep manual JEs for adjustments; everything operational flows from events.

## 6. Expenses (+ advances, card transactions, categories/policies)

### Exists today
- Expense draft→submit (approval engine ✅)→approve→reimburse; categories with
  policy fields; advances create/list; card-import page; `mine` filter.

### Half-baked / missing (verified)
- ⚠️ Policy fields entirely unenforced: `maxAmountMinor`,
  `receiptRequiredAboveMinor`, `policyViolation` never checked/set.
- ⚠️ Mileage kind in schema, no mileage form/calculation UI.
- ⚠️ Advances: no approval surfacing, no settlement against expenses
  (`settledMinor` dead).
- ⚠️ Card transactions: import exists, **matching logic/UI absent**
  (`cardTransactionId` never set).
- ⚠️ `billable` + `billedInvoiceId` exist; no expense→invoice-line conversion.
- ❌ No receipt-upload widget on the form (field exists); no per-diem; no
  multi-line expense reports (batch approval).

### Enterprise target model
*Benchmark: Zoho Expense.*
- Policy engine at submit: limit/receipt checks set `policyViolation`, route to
  stricter approval, or block; mileage form (distance × rate by category);
  advances approval + settlement (advance balance offsets reimbursement);
  card-transaction matching screen (suggest by amount/date, one-click create);
  billable expenses pulled into invoice builder; expense report batches;
  receipts via P9 attachments with thumbnail viewer; spend analytics
  (category/employee/project, policy-violation report).

## 7. Customer portal

### Exists today
- Separate identity plane ✅ (portal JWT can never be staff token); login/
  logout; estimates list/detail with accept/reject (stamped, evented);
  invoices list/detail read-only; `customerVisible` default-deny ✅.

### Missing (verified)
- ❌ PDF downloads; payment submission ("I paid, here's the reference" →
  staff confirmation queue); comments/questions on documents; password
  reset/invitation onboarding (staff-set passwords only); order/shipment
  tracking; document sharing (designed in plan §6.5, unbuilt).

### Enterprise target model
- Portal v2: invite + reset flows, estimate/invoice PDFs, payment-claim
  submission → staff confirm loop, scoped comments (P9), shipment tracking
  view, branded per workspace. Strict default-deny preserved.
